# 基金公司角色功能规范

## 背景说明
目前系统已存在四种用户角色：admin（管理员）、partner（合伙人）、client（客户）、waiter（服务员）。为拓展业务需求，需要在admin、web、mobile三个应用中新增"基金公司"角色，使基金公司能够发布基金产品、与客户进行对话、编辑内参公众号等功能。

## 变更内容

### 1. 数据库层变更
- 在user_roles表中新增"基金公司"角色（code: fund_company）
- 在users表中更新对应用户的role字段

### 2. Admin应用变更
- 在系统设置-用户角色设置中允许添加"基金公司"角色
- 导航菜单中增加"基金公司管理"模块，用于管理基金公司用户
- 产品管理功能中对基金公司角色开放创建和编辑权限
- 客服管理功能中对基金公司角色开放查看对话权限

### 3. Mobile应用变更
- 在"我的"页面功能管理区块中增加基金公司角色对应的功能入口
- 基金公司可使用的功能：
  - 发布基金产品
  - 与客户对话
  - 管理内参公众号

### 4. Web应用变更
- 登录后根据用户角色显示对应功能菜单
- 基金公司角色可访问产品管理相关页面
- 基金公司角色可访问客服对话相关页面
- 基金公司角色可访问内参公众号相关页面

## 影响范围

### 受影响的功能模块
- 用户角色管理系统

## 新增需求规范

### 需求：新增基金公司角色

#### 场景：数据库角色配置
- **当** 管理员在系统设置中新增"基金公司"角色
- **则** 角色信息保存到user_roles表，包含角色名称"基金公司"和角色代码"fund_company"

#### 场景：基金公司用户登录
- **当** 拥有fund_company角色的用户登录admin应用
- **则** 侧边栏显示"基金公司管理"菜单项，可查看和管理所属基金公司信息

#### 场景：基金公司发布基金产品
- **当** 登录用户角色为fund_company
- **则** 可以在产品管理页面创建、编辑、发布基金产品

#### 场景：基金公司与客户对话
- **当** 登录用户角色为fund_company
- **则** 可以查看分配给自己的客户对话，进行实时沟通

#### 场景：基金公司编辑内参公众号
- **当** 登录用户角色为fund_company
- **则** 可以进入内参管理模块，创建、编辑、发布公众号文章

## 修改需求规范

### 需求：admin端角色显示优化
原需求：角色显示为中文或英文代码
修改后：根据用户角色动态显示角色名称，包括新增的"基金公司"角色

### 需求：mobile端功能管理区块
原需求：根据角色显示对应的功能入口
修改后：
- waiter/cs角色：显示"客户对话"、"消息查阅"、"申请办理"
- admin角色：显示"消息查阅"、"申请办理"、"功能设置"
- partner角色：显示"我的客户"、"我的佣金"、"我的投资"
- customer角色：显示"资产状况"、"资金往来"、"交易记录"
- **fund_company角色**：显示"产品管理"、"客户对话"、"公众号管理"

## 技术实现注意事项

1. 数据库迁移需要添加新的角色数据
2. 各端的角色判断逻辑需要更新，添加fund_company的case
3. 权限控制需要在API层和UI层双重校验
4. 基金公司角色应该有独立的产品线，只能管理自己发布的基金产品

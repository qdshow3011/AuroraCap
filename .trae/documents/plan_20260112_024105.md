# 实现自动产生消息机制

## 1. 需求分析

设计自动产生消息机制，在以下事件发生时生成相应的消息：

1. 用户注册成功后，生成两条消息：

   * 给注册用户："感谢您的信任，你的注册已成功！邀请人为“邀请人姓名”"

   * 给邀请人："您邀请的用户“（用户姓名）”已经注册成功，感谢您的付出！"

2. 用户注册信息变更时，生成消息：

   * 给用户："您的信息已经修改成功，感谢您！"

3. 用户涉及基金申购申请、赎回申请、入金申请、出金申请等，生成消息：

   * 给用户、服务员和管理员："\[用户姓名],你的\[申购/赎回/入金/出金]申请已经提交成功，我们正依据约定努力为您办理中，谢谢！"

4. 管理员（或服务员）操作了入金/出金管理、申购/赎回管理、持仓管理、余额管理、合同管理时，对相关客户生成相应的信息。

## 2. 技术方案

### 2.1 消息生成工具类

创建一个消息生成工具类，封装各种类型消息的生成逻辑：

```typescript
// src/utils/message-generator.ts
import { supabaseClient } from '../main';

interface GenerateMessageOptions {
  content: string;
  category: string;
  audienceType: string;
  userId?: string;
}

export const messageGenerator = {
  // 生成用户注册成功消息
  async generateRegistrationMessages(userId: string, userName: string, inviterId?: string, inviterName?: string) {
    // 给注册用户的消息
    await this.generateMessage({
      content: `感谢您的信任，你的注册已成功！邀请人为"${inviterName || '无'}"`,
      category: 'system',
      audienceType: 'user',
      userId
    });

    // 给邀请人的消息
    if (inviterId && inviterName) {
      await this.generateMessage({
        content: `您邀请的用户"${userName}"已经注册成功，感谢您的付出！`,
        category: 'system',
        audienceType: 'user',
        userId: inviterId
      });
    }
  },

  // 生成用户信息变更消息
  async generateInfoUpdateMessage(userId: string) {
    await this.generateMessage({
      content: '您的信息已经修改成功，感谢您！',
      category: 'system',
      audienceType: 'user',
      userId
    });
  },

  // 生成基金交易申请消息
  async generateFundTransactionMessage(userId: string, userName: string, transactionType: '申购' | '赎回' | '入金' | '出金') {
    const content1= `${userName},你的${transactionType}申请已经提交成功，我们正依据约定努力为您办理中，谢谢！`;
    const content2= `${userName}的${transactionType}申请已经提交成功请依据约定努力为您办理中，谢谢！`;
    // 给用户的消息
    await this.generateMessage({
      content1,
      category: 'transaction',
      audienceType: 'user',
      userId
    });

    // 给服务员的消息
    await this.generateMessage({
      content2,
      category: 'transaction',
      audienceType: 'waiter'
    });

    // 给管理员的消息
    await this.generateMessage({
      content2,
      category: 'transaction',
      audienceType: 'admin'
    });
  },

  // 生成管理员操作消息
  async generateAdminOperationMessage(userId: string, operationType: string, content: string) {
    await this.generateMessage({
      content,
      category: 'admin',
      audienceType: 'user',
      userId
    });
  },

  // 通用消息生成函数
  private async generateMessage(options: GenerateMessageOptions) {
    await supabaseClient
      .from('system_messages')
      .insert({
        content: options.content,
        category: options.category,
        audience_type: options.audienceType,
        user_id: options.userId,
        created_by: 'system',
        created_at: new Date().toISOString()
      });
  }
};
```

### 2.2 触发点识别与集成

需要在代码库中找到以下事件的触发点，并集成消息生成逻辑：

#### 2.2.1 用户注册

查找用户注册相关的代码，通常在 `src/pages/auth/register.tsx` 或类似文件中。

#### 2.2.2 用户信息变更

查找用户信息更新相关的代码，通常在 `src/pages/profile/edit.tsx` 或类似文件中。

## 4. 预期效果

* 用户注册成功后，注册用户和邀请人都会收到相应的消息

* 用户信息变更后，用户会收到相应的消息

* 用户提交基金交易申请后，用户、服务员和管理员都会收到相应的消息

* 管理员操作客户数据后，相关客户会收到相应的消息

* 所有消息都会显示在消息管理页面中，支持查看、编辑和删除操作

## 5. 注意事项

1. **性能考虑**

   * 消息生成操作应异步执行，不阻塞主流程

   * 考虑使用事务确保数据一致性

2. **错误处理**

   * 消息生成失败不应影响主流程

   * 添加适当的错误日志

3. **数据安全**

   * 确保消息内容不包含敏感信息

   * 确保消息只发送给授权用户

4. **可扩展性**

   * 设计灵活的消息生成机制，便于添加新的消息类型

   * 考虑使用模板系统管理消息内容

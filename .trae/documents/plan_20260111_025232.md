# 申购申请同时写入subscription_redemption和deposit_withdrawal表的实现方案

## 功能需求
在申购申请页面提交申请后，需要同时执行两个数据库写入操作：
1. 写入subscription_redemption表（已有功能）
2. 将该投资资金的入金申请写入deposit_withdrawal表，状态为processing

## 实现步骤

1. **修改SubscriptionApplicationScreen.tsx的handleSubmit函数**
   - 在subscription_redemption插入成功后，添加deposit_withdrawal表的插入逻辑
   - 入金申请数据包括：
     - user_id: 与申购申请相同的用户ID
     - type: 'deposit'（入金类型）
     - amount: 投资金额
     - status: 'processing'（处理中状态）
     - notes: 包含产品名称的自动入金说明

2. **数据准备**
   - 使用现有投资金额作为入金金额
   - 使用产品名称生成入金备注
   - 确保用户ID和产品信息可用

3. **错误处理**
   - 分别处理subscription_redemption和deposit_withdrawal的插入错误
   - 如果任一插入失败，向用户显示错误信息

## 具体代码修改

在`handleSubmit`函数中，在subscription_redemption插入成功后添加：

```typescript
// 准备deposit_withdrawal数据
const depositData = {
  user_id: userInfo?.id || 'test_user_id',
  type: 'deposit',
  amount: amount,
  status: 'processing',
  notes: `Automatic deposit for subscription to ${getProductName(selectedProduct)}`
};

// 插入deposit_withdrawal记录
const { error: dwError } = await supabase
  .from('deposit_withdrawal')
  .insert(depositData);

if (dwError) {
  console.error('Failed to insert deposit_withdrawal:', dwError);
  Alert.alert(t.error, lang === 'zh' ? '提交失败，请稍后重试' : 'Submission failed, please try again later');
  return;
}
```

## 预期效果
- 用户提交申购申请后，系统会自动生成一条对应的入金申请记录
- 入金申请状态为"processing"，清晰标识正在处理中
- 入金备注包含产品名称，便于追踪
- 两个表的写入操作都成功才返回成功信息，确保数据一致性
